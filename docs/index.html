01 / Capabilities

Private conversations.
Invite-only access.

Individual and group chats with local history and explicit access controls.

01 / LIFECYCLE

Individual and group chats

Personal or group rooms with per-chat names and expiring invites. Revocation blocks invite-issued sessions; closure pauses messaging while preserving history. See lifecycle rules.

02 / REAL TIME

Live delivery and status

WebSocket delivery with HTTP polling, separate delivery/viewing confirmations, and optional presence. The web app reconnects with persisted send retries.

03 / TRANSPORT

Encrypted messages and files

The web app encrypts locally, including reactions; participants verify peer fingerprints separately. Text/cards arrive independently of encrypted media transfers, with files up to 1 MiB. Filenames and types stay encrypted. Automatic JPEG/PNG/WebP previews stay local and can be hidden until revealed; see media limits. HTTPS protects sessions.

04 / ADMISSION

Participant slots that seal

Two personal-room slots; optional group limits. Opening an invite claims no slot; joining claims one and authenticated reconnects reuse it.

05 / ACCESS

Optional room passwords

Add a password to an invite, protected by salted scrypt and rate-limited guesses.

06 / RETENTION

A queue, not an archive

The server temporarily stores encrypted messages and files. Each recipient's durable ACK or seven-day default expiry removes their ciphertext. Room records and bounded retry metadata remain; local history and downloads survive server deletion.

API reference ↗
  1. Persist admission credentials, then activate an invite.
  2. Send per-recipient encrypted envelopes over HTTP.
  3. Receive messages over WebSocket or HTTP polling.
  4. Persist locally, then acknowledge exact delivery.

Local /docs provides OpenAPI. Use renewable sessions, first-frame WS authentication and an agreed encryption format.

BUNDLED WEB APP

Open the messenger at /client.

The web app uses non-exportable P-256 keys and encrypted local history. Origins, profiles and devices have independent identities; keys and history do not sync. Clearing browser storage can permanently lose them. Group copies multiply bandwidth/storage. Verify peer fingerprints separately. Links open only on click; optional previews load only when enabled on the device. No recipient forward secrecy, post-compromise recovery or server malware inspection. Use a dedicated, trusted browser origin. Increasing pre-1.0 version deployments reset all server state; same-version redeployments preserve it. Browser-local keys/history remain. See the setup and recovery guide.

04 / Self-host

Self-host with
Docker or Python.

The web messenger, admin interface and FastAPI backend ship together. Run with Python or Docker Compose; expose HTTPS and keep administration private.

Deployment guide ↗ Python setup ↗
DOCKER COMPOSESHELL
git clone https://github.com/vladleesi/sideword.git
cd sideword
cp .env.example .env

# Set a random signing secret and admin credentials.
# Set SIDEWORD_PUBLIC_URL to your HTTPS origin.
docker compose up -d --build

Configure .env, persistent storage and private administration before exposing HTTPS. Open http://localhost:8000/client for chat and /admin/links for invites. Releases do not deploy your application.
